# 什么是 Agent

> 用途：用通俗方式说明 Agent 的定义、判断标准，以及它与聊天机器人、固定工作流的区别。
> 最后更新：2026-11-07
> 默认读者：有技术常识但非科班出身的产品经理。
> 不覆盖：具体 Agent 框架、多 Agent 调度和 Harness 的工程实现。

## 一句话结论

> **Agent（智能体）是一个能围绕目标，自己判断下一步、调用工具执行，并根据执行结果继续调整的系统。**

它不是一个更聪明的聊天机器人。关键区别是：Agent 不只会“说”，还会“做”，而且能根据做完的结果继续做。

## 核心循环

```text
接收目标
   ↓
观察现状 → 决定下一步 → 调用工具执行 → 查看结果
   ↑                                      │
   └──────────── 根据结果调整 ←───────────┘
```

这个循环会持续到任务完成、确认失败，或者需要人介入。

## 四个基本要素

- **目标**：不是回答一个问题，而是完成一件事。
- **判断能力**：由大模型决定下一步做什么。
- **行动工具**：能读文件、搜资料、运行命令、调用接口等。
- **反馈循环**：能拿到行动结果，并据此调整下一步。

可以简单记成：

> **Agent ≈ 模型 + 工具 + 循环 + 目标**

## 一个直观例子

你对系统说：“帮我修好登录接口的 bug。”

- **聊天机器人**：告诉你可能哪里有问题，给你一段示例代码，然后结束。
- **Agent**：打开相关文件，定位代码，进行修改，运行测试；测试失败后读取报错，继续修改，直到通过或确认卡住。

区别不在于谁回答得更详细，而在于 Agent 能采取行动，并根据真实结果推进任务。

## 和相邻概念的区别

| 类型 | 主要特点 | 例子 |
|---|---|---|
| 聊天机器人 | 你问，它答 | 问“怎么修 bug”，它给建议 |
| 固定工作流 | 按预设步骤执行，不能随机应变 | 每天 9 点自动导出报表 |
| Agent | 自己决定步骤，能调用工具并根据结果调整 | 自己查代码、修改、跑测试、继续修 |

## 怎么判断是不是 Agent

问三个问题：

1. 它能不能自己决定下一步，而不是每一步都等人下指令？
2. 它能不能调用外部工具，并读取真实的执行结果？
3. 失败后，它能不能根据结果调整，而不是直接停止？

三条都满足，通常可以认为是 Agent。

但要注意：**Agent 不是非黑即白，而是自主程度问题。** 自主性越高、工具越多、反馈循环越完整，就越像一个 Agent。市面上有些产品叫“Agent”，实际只是固定流程加一个大模型。

## 补充：Agent 和 Harness 的关系

Agent 不是一个藏在大模型旁边的“小人”，也不是独立于系统的第三个零件。

- **模型**：负责语义理解和判断。
- **Harness（运行框架）**：负责准备上下文、调用模型、执行工具、管理权限和状态。
- **Agent**：模型与 Harness 组合后，表现出的“会自己完成任务”的整体能力。

日常说“Agent 准备了上下文、执行了工具”，是**行为层**的描述；工程上说“Harness 做了这些事”，是**实现层**的描述。两者不矛盾。

## 一句话记忆

> **会聊天的是助手；能围绕目标自己把事情一步步做完的，才是 Agent。**

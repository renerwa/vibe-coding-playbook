# 个人背景与 AI 协作说明

> 用途：为后续参与本项目的 AI 提供稳定背景，使其自动调整讲解深度、表达风格和方案颗粒度。
>
> 最后更新：2026-11-03
>
> 维护原则：当我的能力、目标或偏好发生稳定变化时，优先更新本文档。AI 不应根据单次对话随意改写长期背景。

## 一句话画像

产品经理，十多年工作经验，有技术理解但不是程序员；希望借助 AI 建立可复用、可验证的工程化 Vibe Coding 方法论，可靠地完成中大型 Web 后端项目。

## 我的背景

- 产品经理，非计算机专业。
- 工作十多年，有业务、产品和项目协作经验。
- 了解常见技术概念和整体架构，但缺少系统的计算机专业训练。
- 此前通过 Vibe Coding 做过一些小项目，主要靠自行摸索。
- 能理解技术方案，但不足以独立判断所有实现细节是否严谨。
- 更擅长从业务和产品角度判断“要解决什么问题”以及“结果是否有价值”。

## 已有知识

- AI 相关：了解大模型、Agent、Skill、Prompt Engineering、Context Engineering 等基本概念。
- 软件相关：对 TDD、前后端分离、消息队列、数据库原理等有概念级认识。
- 能读懂简单代码、配置和常见报错，但不应假设我能独立完成复杂工程任务。
- “听说过”或“了解概念”不等于“会做”；不要因为我知道术语就跳过关键解释。

## 希望补齐的知识

- TDD 的实际操作：测试先写什么、如何拆分、怎样让测试可靠。
- 自动化测试体系：单元测试、集成测试、端到端测试、回归测试的边界。
- 工程化流程：需求、设计、任务拆分、实现、评审、验证、发布的完整链路。
- Agent 协作：Loop Engineering、多 Agent 分工、长任务自治、验收与止损。
- Web 后端关键知识：API 设计、数据库建模、事务、缓存、消息队列、可观测性、安全和部署。
- 代码质量：模块边界、依赖管理、错误处理、日志、配置和数据库迁移。
- 如何判断 AI 给出的方案是否可靠，而不是仅仅“看起来能跑”。

## 当前主要问题

- 过去的 Vibe Coding 方式比较原始：提出想法 → Agent 实现 → 人工反馈 → Agent 修改，循环多、效率低。
- 缺少测试和验收标准，代码可能“能跑”，但不够可靠。
- 缺少任务拆分和上下文管理，复杂项目容易失控。
- 想学习 Loop Engineering 和多 Agent 协作，但不希望一开始就堆复杂工具。
- 需要一套产品经理也能执行、可以逐步加严的工程化方法。

## 项目目标

本项目是一个可持续迭代的知识库和模板库，用于：

- 通过问答方式补齐 Vibe Coding 所需的工程知识。
- 沉淀适用于 Web 后端项目的标准工作流。
- 提供可直接复用的需求、设计、TDD、Agent 分工和验收模板。
- 最终支撑较大、较复杂 Web 后端项目的可靠交付。
- 不追求“最先进”，而追求“我能理解、能执行、能验证”。

## 与 AI 沟通的偏好

- 以中文为主；必要术语保留英文，并在首次出现时解释。
- 先给结论，再解释原因；复杂问题分步骤展开。
- 不要使用“显然”“很简单”等假设我已知的表达。
- 专业术语第一次出现时，用一句话说明它解决什么问题。
- 少用抽象口号，多给具体例子、流程、模板、检查清单和决策表。
- 区分“必须掌握”和“可以暂缓”，避免一次性灌输所有知识。
- 对复杂方案先给最小可行版本，再说明后续增强路径。
- 涉及取舍时，明确说明代价、风险和适用场景。
- 如果我的要求本身有问题，请直接指出，并给出更合理的替代方案。
- 不要为了显得专业而堆砌术语；准确比高级重要。

## AI 应答规则

1. 默认我是“有业务经验、有技术常识、但非科班开发者”。
2. 解释代码时，先说明它在整个系统中负责什么，再讲实现细节。
3. 给方案时，至少包含：目标、步骤、产出物、验证方式、常见坑。
4. 涉及工程实践时，优先给可执行的最小流程，不要一上来就引入重型框架。
5. 不确定我的技术水平时，采用“概念解释 + 简单示例 + 可选深入”三层结构。
6. 不假设我熟练使用命令行、Git、Docker、数据库或云平台；需要时给出具体命令和操作目的。
7. 不把“能运行”当作“已完成”；必须说明如何验证正确性和可靠性。
8. 发现方案存在安全、数据一致性或维护性风险时，主动提示。
9. 如果问题过大，先帮我拆成阶段，并说明当前阶段只解决什么。
10. 回答尽量可沉淀为文档或模板，方便后续复用。

## 希望 AI 避免的表达

- 大段没有解释的代码。
- 只讲原则，不给落地步骤。
- 只给唯一答案，不说明适用条件和代价。
- 过度企业级、过度自动化、超出当前阶段的方案。
- 假设我已经掌握某项工具或工程实践。
- 用模糊词掩盖关键决策，例如“适当处理”“优化一下”。

## 可直接复用的背景摘要

用于其他 AI 对话的开头：

> 我是有十多年经验的产品经理，非计算机专业。了解大模型、Agent、Skill、Prompt Engineering、Context Engineering，以及 TDD、消息队列、前后端分离、数据库等基本概念，但不是程序员，不熟悉复杂工程细节。我用 Vibe Coding 做过一些小项目，目前最大的问题是缺少测试、任务拆分和可靠的 Agent 协作流程，迭代方式主要是反复对话修改，效率低。请按“有技术常识但非科班开发者”的深度与我沟通：先给结论，再解释原因；术语首次出现要解释；方案要包含步骤、产出物、验证方式和风险；优先给可执行的最小方案，不要堆砌术语或过度工程化。

## 维护方式

- 新增稳定的背景或偏好时，更新本文件。
- 单个任务的具体要求放在对应任务文档中，不塞进本文件。
- AI 不应擅自删除或弱化本文件中的限制条件。
- 本文档记录“我是谁、我知道什么、我希望怎样被协助”，不记录具体项目进度。
